# 输入与执行契约

## 三表成员关系

`a_top10` 与 `premium_top10` 读取各自正式Top10文件；Decision读取 `decision.html` 主表实际按 `report_index.json.reports[0].action_url` 渲染的 `action_plan.stage_watchlist`。Decision 的页面排名必须使用 `stage_watch_rank`；同一行的 `rank` 只是全量 `candidates` 池排名，不得用于三表成员关系。每张表最多取实际展示的前10名，不足10名时按实际数量，绝不从全量候选池补票。求交集前统一证券代码、要求显式正整数连续页面排名，并检查重复代码与重复排名。Premium的 `WATCH/EXCLUDED` 和Decision的 `REJECT/SHADOW_ONLY/BUY` 只作为特征，不改变“是否出现在主表前10名”。

每次读取先分别解析 `a-top10/main` 与 `top10-decision/main` 的完整远端 commit SHA，再用该 SHA 读取同一仓库内的指针、日期文件和索引。禁止在同一次快照中直接读取可变的 `raw/.../main/...`。a-top10 的指针 `run_id/commit_sha` 必须与日期CSV一致；Premium指针必须明确 `ok=True`；Decision索引的 `latest_report_date`、`reports[0].report_date` 与行动文件 `report_date` 必须一致。

每个冻结信号除保存三源内容哈希和固定commit外，还保存三张实际展示名单的完整 `ranked_rows`（排名、代码、名称）。该快照只用于输入审计与反事实研究；正式Signal成员资格仍只能由三表严格交集产生，绝不能用非交集成员补票。

Premium CSV 若出现重复表头，仅在每行重复值一致（数值等价也视为一致）或仅一侧非空时安全合并，并记录源质量警告；任一行存在冲突值则阻断。Decision 的 `stage_watch_display_limit` 必须为10；`stage_watch_count` 必须等于 `stage_watchlist` 行数，并等于 `min(stage_watch_eligible_count, 10)`。每个主表成员还必须能按代码及原始 `rank` 唯一映射回 `candidates`，且 `observation_rank` 与 `stage_watch_rank` 一致；任何不一致均阻断输入，绝不回退全量池。`decision_p_fill/decision_e_ret/decision_ev/decision_cost/decision_risk_penalty` 是辅助数值特征：缺失时记录覆盖率警告但保留该实际展示成员；非空值仍必须是有限数，且概率、成本和风险惩罚必须满足合法范围。

严格交集：

```text
intersection = codes(a_top10) ∩ codes(premium_top10) ∩ codes(decision_table)
```

交集为零是合法结果。交集有几支就保留几支，每一支都进入独立影子账本并接受同一套T日开盘买入与T+1退出验证。固定第1/2/3名仍作为三个长期独立序列分别统计，不会限制第4名及以后进入影子验证，也不会发生名次补位。

## D时点特征与正式排序输出

`formal_features_v2` 采用显式白名单，不会把源行任意展开成特征。`feature_contract_v2_2` 为每个生产字段声明角色、来源、D时点策略、缺失策略、信任等级和 `model_eligible` 学习资格，并生成可复核SHA-256。学习引擎仅允许13个预注册字段：1/5/20日收益、CVaR与20日最大回撤、20日平均成交额与成交量、三源独立名次与分歧、两个阶段one-hot；上游自报值、综合分、重复名次统计和数值化阶段均禁止进入学习。市场特征只允许使用日期不晚于D且最后一根恰好等于D的连续历史；至少需要21根有效日线。重复日期、乱序、未来K线、D日尾部缺失、价量字段不自洽均使市场特征失效。失效候选不会被删除，而会触发同日整组Borda共识降级和 `NO_TRADE`。学习冠军的缺失率必须按其完整 `feature_order` 在中位数填补前计算；`avg_amount_20d` 与 `avg_volume_20d` 是两个独立字段，任一缺失都单独计数，不得静默互相替代。

正式预测契约为 `ranking_prediction_v2`，预测时点固定为 `D_PRIOR`。每个冻结候选必须保存：

- 兼容字段 `p_fill`、`expected_fill_ratio`（开盘成交口径下固定为1）；
- `conditional_net_return_mean` 与 `conditional_net_return_q10/q50/q90`；
- `p_exit_delay`、`expected_delay_days`；
- 辅助目标 `p_promotion`；
- `expected_shortfall`、`uncertainty`、`utility`；
- `gate_decision`、`gate_reasons` 与 `ranking_fallback`。

收益预测以T日未复权开盘价成交为统一前提，并且已经扣除与影子账本同口径的预估费用。10/50/90分位会在进入风险效用和页面前做确定性的单调投影。晋级概率只作独立辅助预测，不能直接充当最终收益排序目标。

策略门槛同时要求市场特征完整、净收益均值和第10分位严格为正、退出延迟风险不过高、风险效用严格为正；成交概率不再参与门槛。`gate_decision` 只表示正式策略是否可交易，候选的影子 `action` 始终为 `SHADOW`，不能把门槛不通过混写成没有影子记录。

## `single_stock_research_audit_v1` / `single_stock_snapshot_v3`

两层契约已接入新D日信号的冻结流程。系统先完成严格交集、冠军排名和 `shadow_order_spec_v1`，将核心Signal、全部候选和影子账本原子落盘并标记研究待完成，之后才启动独立可终止的后置进程生成 `single_stock_research_audit_v1`。因此单票研究成功、失败、超时或缺失都不能反向改变或擦除交集、名次、订单或账本。失败必须落一份有明确原因和SHA-256指纹的 `UNAVAILABLE` 信封，不能退化为空对象；旧冻结信号不事后回填或重算，看板对其保持 `null`。

每支严格交集候选的可用审计对象内含一份 `single_stock_snapshot_v3`、D日候选分析白名单摘要、冻结订单摘要和D日分钟状态代理。`single_stock_snapshot_v3` 保存候选标识、三源名次、D日冻结时点、逐字段来源、`known_at`、抓取时间、内容哈希、缺失原因与硬门控结果。整个研究信封的指纹覆盖所有嵌套字段；分钟输入另以规范化日期、时间、OHLC、量额、最小价位、来源、复权和时间语义计算内容指纹。全部规范分钟行以 `single_stock_minute_archive_v1` 独立追加归档：路径按年/D日/证券代码/对象SHA组织，使用 `mtime=0` 的确定性 `.json.gz`，`artifact_sha256` 绑定解压后的规范JSON。抓取时间只在轻量引用中，不改变对象地址；同内容重试复用原对象，供应商内容修订才新增对象。研究快照只保存相对路径、对象SHA、分钟内容SHA、条数、完整性与供应商引用，不把240根行情塞进state或dashboard。训练数据集明确忽略整个单票审计对象，未经新特征契约、前推验证与模型晋级不得进入冠军模型。

研究硬门控的唯一合法状态为：

- `PASS`：所需证据完整，且没有命中已定义的确定性阻断条件。
- `BLOCK`：证据足以确认停牌、ST、退市整理、交易规则冲突等确定性风险。
- `UNKNOWN`：关键证据缺失、冲突或无法验证。未知不能被当作 `PASS` 或 `BLOCK`。

在V3首阶段，这三种状态都只是 `shadow/audit-only` 的研究标签。它们不改变三表严格交集成员，不删除、补入或换入候选，不改写名次、冠军分数、策略门槛或冻结订单规格。即使是 `BLOCK` 或 `UNKNOWN`，交集候选仍照常进入全部候选影子账本。

系统已定义并接入 `point_in_time_security_master_v1` 的最小生产读取路径。路径由受限的 `config.paths.security_master` 显式传入研究批次，批次内只加载一次，不在单票函数中暗用默认文件。每条证券记录必须声明有效日期区间、`known_at`、`fetched_at`、供应商、数据集版本、修订号、可审计来源地址和内容指纹；只有同时不晚于D日冻结时点的记录才可使用。字段契约覆盖停牌、ST、退市整理、交易规则是否已核验、所属交易板块、涨跌幅限制和最小价位。规则核验为真时，板块、涨跌幅限制和最小价位必须同时存在。

仓库随附的 `data/security_master.v1.json` 是合法但为空的启动数据集，不伪造任何证券状态。没有可用记录时，缺失事实的来源时间使用数据集真实 `generated_at`，不伪写成D日冻结时点；若数据集晚于D日冻结时点生成，则整份单票研究证据失败关闭，不得事后冒充D日缺失证据。字段缺失或没有合格记录时，相应值一律保存为 `null`、硬门控为 `UNKNOWN`；禁止根据股票代码、名称、交易板块猜测，也禁止用系统配置中的默认价位冒充证券主数据。只有装载经授权且有来源链的点时记录后，研究门控才可能成为 `PASS` 或确定性的 `BLOCK`。这些状态仍是审计标签，不改变当前交集、排名或订单。

### D日240分钟收盘状态代理

分钟状态代理只允许使用D日连续竞价时段的完整240个一分钟区间：上午120个区间与下午120个区间。每根必须日期严格等于D，`price_adjustment=NONE`，时间标签必须统一归一为区间左边界，且时间唯一、严格有序、价量额口径可验证。

完整契约通过后，才可根据冻结的D日涨停价计算是否触及涨停、首次/最后收盘等于涨停价的时间、分钟收盘状态的离开/重新进入次数、收盘等于涨停价的分钟数与全日OHLC一字代理。字段名为兼容可继续使用 `break/reseal/sealed/one_price`，但语义始终是 `MINUTE_CLOSE_PROXY`：绝不证明盘口真实封板、开板、回封、撤单、队列或可成交性。完整240根已证实从未触及时，代理计数可合法为0；任一区间缺失、重复、跨日、复权口径错误或时间语义不可验证时，代理必须标记为 `UNKNOWN/UNAVAILABLE`，所有无法证实的计数保持 `null`，不得用0代替未知。

当前腾讯分钟回退只覆盖特定的T+1退出时间窗，不构成D日240分钟生命周期证据；只有完整性校验通过的D日分钟源才可生产该字段。

生产采集使用独立的短预算：单请求最多3秒、只尝试1次、最多5票并行，整批在可终止子进程内有15秒硬截止。超时、抓取、归档或构建异常只能形成 `UNAVAILABLE` 警告，不得改变或回滚已落盘的交集、排名、冻结订单与账本；配置若试图让该模块影响交集、排名、订单或声称真实竞价门控已连接，启动时必须失败关闭。

## 日期链

```text
a.trade_date = premium.trade_date = premium.base_date = decision.signal_date = D
a.verify_date = premium.buy_date = decision.exec_date = T
premium.target_date = decision.exit_date = T+1
```

三个上游产物先交叉验证，再由版本化的 `data/trading_calendar_bundle.json` 验证严格的交易日后继关系。Bundle允许逐年加入独立的官方日历，并支持在相邻年度都已认证时跨年计算D/T/T+1。2026条目由上海证券交易所《关于上海证券交易所2026年部分节假日休市安排的通知》固化为 `VERIFIED`：周六、周日及通知列明的休市日均不可作为D/T/T+1。

截至2026-08-09，上交所尚未发布可供本仓库认证的2027年度休市安排。`trading_calendar_2027_candidate.json` 因此只保存查询日期和上交所休市安排索引，明确标记为 `UNVERIFIED_AWAITING_OFFICIAL_NOTICE`，且不包含任何猜测的开市日或休市日。生产遇到2027日期必须失败关闭；不能用周一至周五推断正式开市。待官方通知发布后，必须据通知生成独立年度文件、核验年度与来源，再把Bundle状态显式晋级为 `VERIFIED`。日历缺失、年度未认证、日期非法或并非严格下一交易日时，一律 `INPUT_BLOCKED`。

同一D日首次冻结不得早于北京时间20:00；20:00整允许冻结。已有冻结信号不受该时间门禁影响，仍可结算并只读比较最新源表。冻结后若源表内容哈希或固定仓库commit发生变化，只报告 `SOURCE_REVISION_AFTER_FREEZE`，不得重写原排名。

自动调度先以版本化的上交所交易日历验证上海本地日期；休市日不得请求行情、读取三源或发布伪造批次。交易日分为两个职责隔离的批次：北京时间19:00只处理已冻结名单的T日收盘验证和到期T+1退出，禁止读取三源、求新交集或产生新Signal；21:30才进入三源就绪轮询并冻结D日输出名单。两批次分别使用三次非整点冗余唤醒，早到任务只在同一交易日内等到目标时刻，超过等待预算或跨日必须失败关闭。同日 `SUCCESS/SUCCESS_NO_DUE` 验证和已完成输出必须幂等跳过；`DEGRADED` 验证允许冗余唤醒再次尝试。状态串行锁必须在检出最新 `main` 之前取得，并在计算/数据提交结束后释放；Pages 部署使用独立锁且不强制取消正在进行的生产部署，部署排队不得持有状态锁。两个批次都必须在发布前通过结果自检，并绑定本次任务启动时间，历史成功结果不得复用。19:00以到期义务而非历史累计交易数报告 `due / final / pending_data / delayed / failed`，五类必须完全对账；无到期义务是已执行的 `SUCCESS_NO_DUE`，待数据、延期或失败为 `DEGRADED`。21:30批次仍会幂等重试待处理验证，但不得篡改19:00批次的实际执行时间。源码与页面 `push` 只测试并部署已有页面，禁止触发任一业务批次或写入运行数据。公开页必须并行校验 Pages 与 `main` 看板，选择 `generated_at` 更新的合法载荷并标明数据来源，以避免 Pages 部署延迟遮蔽已提交的名单或验证。

分钟归档随运行数据通过 Git Data API 写入父树上的变更blob；可选递归目录必须是仓库内相对路径，绝对路径、`..`、逃逸仓库的符号链接与原子写临时文件都不得发布。Pages制品不包含state、execution truth或原始分钟gzip；公开页面只展示已校验的轻量研究摘要与引用。

每个冻结D日同时生成同候选域、同开盘买入、同T+1退出、同费用标签的批次反事实：现金、全部候选等权、固定TOP1/2/3、模型序TOP1–3及三源Borda序TOP1–3。任一策略成分未最终结算时，该策略收益必须保持 `null`，不得用已结算子集制造部分收益。旧信号缺少冻结 `rank_borda` 时，只能用三份源快照的实际 `row_count` 按正式Borda公式恢复；任一深度缺失或名次越界均失败关闭。

官方日历依据：[上交所2026年休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)；未来年度公告发现入口：[上交所休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/)。

## T日开盘买入

新信号在D日同步冻结 `shadow_order_spec_v1`。它保存买入日、买入方向、冻结D日涨停限价、按单票资金和费用预留可承受的最大整手数量，以及 `SHADOW_ONLY` 模式。该规格形成后不得随T日行情改写。

T日入场价只读取日期严格等于买入日、`price_adjustment=NONE` 且开盘价为有限正数的未复权日线。通过校验后，D日冻结的申报数量按该开盘价全额计入影子成交，`data_tier=DAILY_BAR`、`label_quality=SHADOW_OPEN_ASSUMPTION`。历史信号若没有冻结订单规格，则按其已冻结的涨停限价、单票资金、整手与买入费用上限恢复申报数量，并记录迁移数量口径；不得用事后开盘价扩大仓位。

当前系统没有可持续产出T日9:25虚拟参考价路径、匹配量、未匹配买卖量、前方队列或券商成交回报的生产者，因此当前没有真实的9:25盘口/排队执行门控。T日未复权开盘价只是影子买入基准，不证明真实委托在9:25可成交，也不证明可成交数量、参与率或队列位置。未来即使接入相关数据，也必须以独立版本契约和执行证据等级另行激活，不能因 `single_stock_snapshot_v3` 的存在就宣称已经接入。

`data/execution_truth.v1.json` 继续保留券商成交日志或逐笔回放的审计证据，但不覆盖本系统统一的开盘价影子入场口径。未复权日线缺失、日期错误、复权口径错误或开盘价非法时状态为 `BUY_UNVERIFIABLE`，收益保持 `null`，不会显示为0%。

## T日收盘验证

每支实际交集候选都保存冻结的 `晋级目标`（目前只接受 `2→3` 或 `3→4`）、D收盘价、涨停机制百分比与预计涨停价。Decision 的 `d_close` 是主值，Premium 的 `close_T` 是独立交叉校验值；两者价差超过0.005、非有限正数，或预计涨停价与D收盘价及涨停机制不一致时，输入契约阻断。

涨跌幅限制价统一按 `D收盘价 × (1 + 涨停机制比例)` 计算，并按交易所四舍五入规则取至0.01元。仅当原始结果恰好处于半个价位边界、Decision因偶数舍入给出相邻的向下价位时允许兼容；系统必须把订单和验证使用的冻结价规范化为交易所四舍五入结果，并记录 `DECISION_LIMIT_PRICE_ROUNDING_NORMALIZED` 警告。普通一价位偏差、超过一价位的偏差或未对齐0.01元的价格仍然阻断，不能为了产出名单而放宽。

页面显示的 `T日涨跌幅 / 是否晋级` 与开盘成交状态相互独立。北京时间T日15:10之前不得请求或写入收盘真值，页面统一显示“待验证”；15:10之后及后续日期可重试，证据不足时显示“待补证”，不能写成“否”。

验证只接受日期严格等于T且 `price_adjustment=NONE` 的无复权日线。`T日涨跌幅` 优先使用供应商正式涨跌幅并与 `T收盘价 / 冻结D收盘价 - 1` 交叉校验；供应商未提供时使用后者。账本内部以T日收盘价在半个最小价位内等于冻结涨停价判定收盘涨停，盘中触及后开板不会被视为晋级；页面不再重复展示“是否涨停”。`是否晋级` 只有在合法晋级目标存在且T日收盘涨停时为“是”。最终真值一经写入即保持幂等，不因后续供应商数据修订而静默改写。

## T+1退出

退出基准使用 `[11:00,11:01)` 至 `[11:04,11:05)` 五个一分钟桶。供应商的分钟结束标签必须先归一化为区间左边界；系统因此不会把10:59–11:04误当目标窗口。执行价固定使用不复权行情，每分钟价格必须由成交额和明确单位的成交量还原，并落在该分钟高低价和合法最小价位范围内；缺一根或数据不自洽即 `EXIT_UNVERIFIABLE`。

每分钟目标为剩余持仓的五分之一，并受保守的5%成交量参与率上限约束。缺少精确跌停价时，一字分钟线按无法成交处理；模拟成交价会限制在该分钟合法价格区间内。11:05仍有余额则 `EXIT_DELAYED`，已卖数量、每笔最低佣金、费用、剩余数量与已处理窗口全部持久化。系统仅在官方交易日历的后续交易日重试，不重放旧窗口；完全退出后按最后一笔真实归属日记账，绝不回填计划T+1。

## 状态语义

- `NOT_AVAILABLE`：该日不存在这个固定名次。
- `PENDING_BUY`：T尚未到达。
- `BUY_UNVERIFIABLE`：T日未复权开盘价尚不可验证。
- `BUY_UNFILLED`：开盘价高于冻结买入限价，或旧版精确真值确认未成交；现金收益为0。
- `OPEN`：已成交，等待T+1。
- `EXIT_UNVERIFIABLE`：退出数据不足，收益未知。
- `EXIT_DELAYED`：按规则仅部分退出，持仓仍存在。
- `CLOSED`：全部退出且费用后收益已结算。

`null` 表示未知或不适用，绝不等同于0。

## 训练标签与模型注册

`training_dataset_v1` 只从已冻结信号和一一对应的影子交易构建，不再联网补特征。每行保留源仓库commit、内容哈希、特征时点与版本；数据集同时保存特征契约指纹、D日组数量和自身内容SHA-256，同一冻结状态必须可重复构建出相同指纹。新口径下合法开盘价的成交标签固定为1；兼容旧状态时未知标签保持 `null`、`BUY_UNFILLED` 仍为0；`CLOSED` 才能产生费用后净收益和实际延迟日。成交头仅为旧模型结构兼容，不参与生产排序或门槛。T日晋级标签与买入状态独立记录。模型晋级样本计数只接受明确标记为 `formal_features_v2` 的冻结行；升级前的历史特征仍保留审计，但不会冒充V2训练样本。

学习模型只接受 `model_artifact_v1` JSON，不加载pickle或可执行代码。训练截止日必须严格早于待排序D日。训练只能生成未认证挑战者；旧式 `validation_passed=true` 不具备任何激活能力。正式晋级必须由 `promotion_certificate_v1` 绑定模型内容指纹、评价数据指纹和全部必需检查报告，并同时通过注册表文件SHA、注册表证书与制品内证书三层校验。任何路径越界、文件缺失、校验和变化、证书缺失或不一致、旧特征版本、未来字段、非法概率头或截止日穿越都失败关闭并回退透明冠军。

## 全部候选组合收益

同一D日的全部实际交集候选构成一个等额影子组合，每支使用相同配置资金。`CLOSED` 使用费用后的 `net_return_on_allocated`，精确确认未成交的 `BUY_UNFILLED` 记为最终现金0；任何候选仍处于非最终状态时，当日组合收益保持 `null`。

当且仅当该日全部候选最终结算，组合收益才取所有候选最终收益的算术平均。历史累计与月度累计均对最终日组合收益复利，而不是直接相加单票百分比。存在最终日与未完成日并存时，累计值标记为暂定；只有未完成日时显示待验证。若候选因延迟退出跨越多个交易日，组合归属日取该组最后一个最终 `return_date`，不得回填计划T+1。
